# Домашнее задание к занятию «Микросервисы: принципы» Доготер Е.Ю.

## Задача 1. API Gateway

Для реализации API Gateway выбран **Kong Gateway**. Он обеспечивает маршрутизацию запросов по конфигурации, проверку JWT-токенов и терминацию HTTPS.

### Сравнение решений

| Критерий | Kong Gateway | Traefik | NGINX |
|---|---|---|---|
| Маршрутизация по конфигурации | Да | Да | Да |
| Проверка аутентификации | Да: JWT, OAuth 2.0, OIDC, key-auth | JWT в Traefik Hub; OIDC в коммерческой версии | Через модули и `auth_request` |
| Терминация HTTPS | Да | Да | Да |
| Плагины | Много готовых плагинов | Middleware и плагины | Модули NGINX |
| Простота настройки | Средняя | Низкая | Средняя |
| Лицензия | Open source + Enterprise | Open source + коммерческая версия | Open source / Plus |

Kong поддерживает декларативную конфигурацию, маршрутизацию, проверку JWT и терминацию TLS.

### Обоснование выбора

Kong выбран, потому что он полностью выполняет требования задания:

- запросы маршрутизируются к нужным микросервисам через декларативный конфигурационный файл;
- можно проверять JWT-токены в заголовке `Authorization`;
- Kong принимает HTTPS-соединение от клиента и терминирует TLS;
- есть готовые плагины для аутентификации, ограничения запросов и логирования;
- DB-less-режим позволяет хранить конфигурацию в Git и применять её через CI/CD. 


## Задача 2. Брокер сообщений

Для обмена сообщениями между микросервисами выбран **Apache Kafka**. Он поддерживает кластеризацию, хранение сообщений на диске, высокую пропускную способность и разграничение доступа.

### Сравнение брокеров

| Критерий | Apache Kafka | RabbitMQ | NATS JetStream |
|---|---|---|---|
| Кластеризация | Да | Да | Да |
| Хранение на диске | Да | Да | Да |
| Высокая скорость | Очень высокая | Высокая | Очень высокая |
| Форматы сообщений | Любой binary payload | Любой binary payload | Любой binary payload |
| Права доступа | ACL по topics и consumer groups | Пользователи, vhosts, permissions | Accounts и permissions |
| Простота эксплуатации | Средняя | Низкая | Низкая |
| Retention и replay | Да | Ограниченно | Да |

Kafka ориентирован на durable event log и высокую пропускную способность; RabbitMQ обеспечивает очереди и маршрутизацию; NATS JetStream поддерживает хранение, репликацию и replay сообщений.

### Обоснование выбора

Apache Kafka выбран по следующим причинам:

- сообщения хранятся на диске в логах и могут быть прочитаны повторно;
- кластер из нескольких брокеров обеспечивает отказоустойчивость за счёт репликации партиций;
- Kafka показывает высокую производительность при больших потоках сообщений;
- формат тела сообщения не ограничен: можно использовать JSON, Avro или Protobuf;
- ACL позволяют разделять права на чтение и запись для разных topics;
- Kafka подходит для событийной архитектуры микросервисов и долгосрочного хранения событий.
